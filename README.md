# EmbodimentApiProbe 0.1.0

Изолированная диагностическая программа для изучения COM API исполнений КОМПАС-3D v25. Она не является частью DesignationEditor2 и не содержит функций изменения или сохранения документов.

## Назначение первой версии

- подключиться к уже запущенному `KOMPAS.Application.7` через ROT;
- не запускать новый КОМПАС;
- получить активный документ;
- найти IID интерфейсов `IKompasDocument3D` и `IEmbodimentsManager` в зарегистрированной TypeLib API7;
- получить интерфейсы через QueryInterface;
- попытаться прочитать количество исполнений, дерево, текущий индекс, базовую часть обозначения, номер исполнения, полное обозначение и признак варианта геометрии;
- записать все успешные и неуспешные COM-вызовы в лог.

## Безопасность

Режим только чтение. В проекте нет вызовов `SetEmbodimentMarking`, `SetCurrentEmbodiment`, `Update`, `Save` или других изменяющих методов. Ничего не изменяется и не сохраняется в КОМПАС.

## Запуск

1. Открыть КОМПАС-3D v25.
2. Открыть тестовую деталь/сборку с исполнениями. Лучше использовать копию.
3. Запустить `EmbodimentApiProbe.exe`.
4. Нажать **Подключиться и считать исполнения**.
5. Сохранить лог кнопкой **Сохранить лог** и отправить его для анализа.

Если EXE отсутствует в архиве, собрать локально через `build-portable.bat` (требуется .NET 10 SDK) либо скачать артефакт из GitHub Actions.

## Исправление 0.1.0 Fix 2

Исправлена загрузка TypeLib API7: сначала выполняется попытка загрузки зарегистрированной библиотеки через `LoadRegTypeLib`, а при неудаче перебираются все зарегистрированные файловые пути через `LoadTypeLibEx`. Ошибка одного пути больше не прерывает остальные попытки. В журнал добавлены подробности каждого способа загрузки.

## Ограничение текущего этапа

В этой версии тестируется только получение интерфейсов и чтение данных. Индексация и структура возвращаемого дерева будут подтверждаться по логам на реальном КОМПАС v25, а не предполагаться заранее.
