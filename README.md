# EmbodimentApiProbe 0.2.1

Изолированная диагностическая программа для изучения COM API исполнений КОМПАС-3D v25. Проект не является частью DesignationEditor2.

## Что умеет

- подключается через ROT только к уже запущенному `KOMPAS.Application.7`;
- получает активный документ и `IEmbodimentsManager` через `QueryInterface`;
- читает количество исполнений, базовую часть, номер исполнения, полное обозначение и признак варианта геометрии;
- выводит подробный журнал, который можно сохранить в TXT;
- содержит отдельный контролируемый тест изменения **только базовой части обозначения** выбранного исполнения.

## Важные ограничения теста записи

**Использовать только на отдельной одноразовой копии документа. Исходный рабочий документ должен быть закрыт.** Перед тестом открой в КОМПАС именно копию и выполни чтение. Для теста требуется выбрать обычное исполнение с непустым номером (например, `-02`), подтвердить, что открыта тестовая копия, и ввести слово `ИЗМЕНИТЬ`. Перед COM-вызовом появится ещё одно окно подтверждения с путём файла, индексом, старым и новым обозначениями.

Программа вызывает только:

`SetEmbodimentMarking(index, ksVMBaseMarking, newBaseMarking)`

Здесь `ksVMBaseMarking = 1`. Сразу после вызова программа фиксирует промежуточные значения (они могут быть ещё не обновлены), выполняет ровно один `RebuildDocument`, повторно подключается к документу и считывает все исполнения. Проверяется новая база и сохранность номера выбранного исполнения, полное обозначение, а также отсутствие изменений в остальных исполнениях.

**Программа не вызывает `Save` и не сохраняет документ КОМПАС.** В версии 0.2.1 она выполняет один вызов `RebuildDocument` только после успешного `SetEmbodimentMarking`. Изменение происходит в открытом документе в памяти КОМПАС. В рамках одного запуска программы разрешена только одна попытка записи для каждого пути документа. После теста закрой тестовую копию без сохранения. Если проверка не прошла или возникла ошибка — тем более не сохраняй документ.

Не запускай тест на рабочем файле и не используй его как массовый инструмент переименования. Это одноразовая проверка поведения API на одном индексе.

## Сборка

Открыть `build-portable.bat` на компьютере с .NET 10 SDK либо запустить workflow `Build EmbodimentApiProbe (portable Windows EXE)` в GitHub Actions. Готовый EXE загружается как артефакт `EmbodimentApiProbe-win-x64`. Workflow использует актуальные основные версии GitHub Actions с Node.js 24.

## Изменения 0.2.0

- добавлен отдельный экран контролируемого теста записи;
- запись доступна только после повторной проверки актуального активного документа и значений выбранного исполнения;
- тест ограничен обычным исполнением с непустым номером;
- перед изменением требуется флажок тестовой копии, слово-подтверждение и отдельное финальное подтверждение;
- после записи проверяется неизменность номера исполнения и ожидаемое полное обозначение;
- в версии 0.2.0 не вызывались `Update`, `RebuildDocument` и `Save`; начиная с 0.2.1 выполняется один контролируемый `RebuildDocument`, `Save` не вызывается.


## Изменения 0.2.1

- после успешного `SetEmbodimentMarking` один раз вызывается `IKompasDocument3D.RebuildDocument()`;
- после перестроения выполняется новое подключение к активному документу через ROT и повторное чтение всего набора исполнений;
- проверяется целевое исполнение и отсутствие изменений в остальных строках;
- известные необязательные пробы `GetEmbodimentsTree` и `GetCurrentEmbodimentIndex`, ранее дававшие ошибки параметров/динамического вызова, исключены из основного журнала;
- `Save` по-прежнему не вызывается.
