# EmbodimentApiProbe 0.2.2

Отдельная диагностическая программа для изучения COM API исполнений КОМПАС-3D v25. Проект не является частью DesignationEditor2.

## Что умеет

- Подключается через ROT только к уже запущенному `KOMPAS.Application.7`; новый экземпляр КОМПАС не запускается.
- Получает активный документ и `IEmbodimentsManager` через `QueryInterface`.
- Читает количество исполнений, базовую часть, номер исполнения, полное обозначение и признак варианта геометрии.
- Содержит защищённый контролируемый тест записи базового обозначения и одного `RebuildDocument()`.
- После перестроения перечитывает весь список и сравнивает его **как мультимножество записей**, не используя API-индексы как постоянные идентификаторы.
- Проверяет сохранение результата после ручного сохранения, закрытия и повторного открытия тестового документа.
- Записывает подробный журнал и позволяет сохранить его в TXT.

## Что обнаружил тест 0.2.1

В реальном документе после `SetEmbodimentMarking` и одного `RebuildDocument` порядок записей изменился. Одновременно базовая часть обновилась у всей группы записей с общей базой: у основной строки без номера и у строки исполнения `-02`. Номер исполнения остался отдельным и неизменным. Проверка 0.2.1 сравнивала строки по старым индексам и поэтому ошибочно сообщила о побочных изменениях.

Версия 0.2.2 учитывает наблюдаемое поведение: ожидает изменение базовой части у всего семейства с одинаковой старой базой, сохраняя у каждой строки её собственный номер исполнения. Все остальные семейства должны остаться без изменений. Порядок строк и индексы после перестроения не имеют значения.

## Этап 1 — чтение

Нажми «Подключиться и считать исполнения». Таблица показывает API-индекс, базовую часть, номер исполнения, полное обозначение и `IsVariant`.

## Этап 2 — запись и перестроение

**Использовать только на отдельной одноразовой копии документа. Исходный рабочий документ должен быть закрыт.** Открой копию в КОМПАС и сначала выполни чтение.

1. Выбери обычную строку исполнения с непустым номером (например, `-02`). Варианты геометрии для данного теста исключены.
2. Введи уникальное новое базовое обозначение, которого ещё нет у другого семейства в документе.
3. Отметь флажок тестовой копии, введи `ИЗМЕНИТЬ` и внимательно прочитай последнее окно подтверждения.
4. Программа повторно проверит активный документ и исходный состав записей, вызовет `SetEmbodimentMarking(index, ksVMBaseMarking, newBase)`, а затем ровно один раз `IKompasDocument3D.RebuildDocument()`.
5. После перестроения программа заново подключится к активному документу и сравнит все записи без привязки к индексам.

Ожидается, что все строки семейства с исходной общей базой получат новую базу, а каждый номер исполнения останется прежним. Основная строка семейства без номера также входит в семейство. Все остальные семейства и количество строк должны остаться неизменными.

### Важные ограничения

- Программа не вызывает `Save`, `Close` или `Open`.
- При неуспешной проверке тестовую копию НЕ сохранять; закрыть без сохранения.
- На один путь документа в рамках одного запуска программы допускается только одна попытка записи.
- Не использовать программу как массовый инструмент переименования и не запускать её на рабочем файле.

## Этап 3 — проверка сохранения после повторного открытия

Доступно только после успешного этапа 2.

1. Не закрывая EmbodimentApiProbe, вручную сохрани тестовую копию штатной командой КОМПАС.
2. Закрой документ в КОМПАС.
3. Заново открой тот же файл с тем же путём.
4. В EmbodimentApiProbe отметь подтверждение, что файл сохранён, закрыт и повторно открыт.
5. Нажми «Проверить сохранённое состояние».

Программа повторно считывает активный документ, проверяет путь и сравнивает весь набор базовых обозначений, номеров, полных обозначений и признаков вариантов с ожидаемым состоянием. Сравнение не зависит от индексов/порядка строк. Сама программа по-прежнему ничего не сохраняет и не закрывает.

Оставляй EmbodimentApiProbe открытым между этапом перестроения и повторным чтением: ожидаемое состояние хранится в памяти диагностической программы. Если закроешь её, данные для автоматического сравнения после повторного открытия будут потеряны; в этом случае можно вручную выполнить чтение и проверить полный список по журналу.

## Сборка

Открыть `build-portable.bat` на компьютере с .NET 10 SDK либо запустить workflow `Build EmbodimentApiProbe (portable Windows EXE)` в GitHub Actions. Готовый EXE загружается как артефакт `EmbodimentApiProbe-win-x64`.

## Изменения 0.2.2

- исправлена проверка результата после перестроения: API-индексы не используются как идентификаторы исполнений;
- ожидаемое изменение рассчитывается для всего семейства с общей базой; номера всех строк семейства должны сохраниться;
- остальные семейства и количество записей сравниваются через мультимножество значений;
- добавлена отдельная проверка сохранённого состояния после ручного Save, закрытия и повторного открытия тестовой копии;
- программный `Save` не добавлен.
