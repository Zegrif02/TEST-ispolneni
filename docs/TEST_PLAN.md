# План проверки API исполнений

## Этап 1 — чтение (подтверждён на КОМПАС-3D v25)

- Подключение к уже запущенному КОМПАС через ROT.
- Получение активного документа.
- Загрузка зарегистрированной TypeLib API7 через `LoadRegTypeLib`.
- Поиск IID `IKompasDocument3D` и `IEmbodimentsManager`.
- Получение `IEmbodimentsManager` через `QueryInterface`.
- Чтение количества исполнений и обозначений по индексам.
- Успешно прочитаны отдельные значения базы, номера исполнения и полного обозначения.

## Этап 2 — изменение семейства и одно перестроение (версия 0.2.2)

### Наблюдение, зафиксированное в тесте 0.2.1

После изменения строки исполнения с номером `-02` и одного `RebuildDocument` КОМПАС переупорядочил записи. Базовая часть обновилась у строки семейства без номера и у строки `-02`; номер `-02` остался прежним. Поэтому сравнение «индекс до = индекс после» некорректно.

### Проверка 0.2.2

Условия:

1. Исходный рабочий документ закрыт; открыта отдельная одноразовая копия.
2. Выполнено свежее чтение.
3. Выбрано обычное исполнение с непустым номером.
4. Новая база уникальна и ещё не используется другим семейством.
5. Пользователь подтвердил тестовую копию и отдельное предупреждение.

Перед записью программа проверяет путь документа, поля выбранного исполнения и мультимножество всех строк. Затем вызывает `SetEmbodimentMarking(index, ksVMBaseMarking, newBase)` и ровно один раз `IKompasDocument3D.RebuildDocument()`.

Ожидаемое состояние строится так: у каждой строки, чья исходная база совпадала с базой выбранного исполнения, базовая часть заменяется на новую; номер исполнения каждой строки остаётся прежним; полное обозначение становится `newBase + originalExecutionNumber`. Все остальные строки ожидаются без изменений.

Успех после перестроения подтверждается, если:

- выбранное исполнение присутствует с новой базой и исходным номером;
- номера всех строк исходного семейства совпадают с ожидаемыми;
- число строк семейства и общее число строк не изменились;
- мультимножество всех полей (база, номер, полное обозначение, вариант геометрии) совпадает с ожидаемым мультимножеством;
- `RebuildDocument` вернул `TRUE` и не выбросил исключение.

Индексы API после перестроения логируются, но не используются для сравнения.

## Этап 3 — проверка сохранения после закрытия/повторного открытия

Только после успешного этапа 2:

1. Пользователь вручную сохраняет тестовую копию в КОМПАС.
2. Закрывает документ.
3. Повторно открывает тот же файл.
4. В программе подтверждает выполнение этих действий и запускает проверку.

Программа подключается к активному документу, сверяет путь и считывает все исполнения. Мультимножество строк должно совпасть с состоянием, ожидаемым после перестроения. `Save`, `Close` и `Open` программой не вызываются.

В рамках теста все изменения выполнять только на отдельной одноразовой копии. При провале этапа 2 копию не сохранять.
