# План диагностики исполнений

## Этап 1 — чтение (версия 0.1.0)

- Подключение к уже запущенному КОМПАС через ROT.
- Получение активного документа и его сведений.
- Загрузка зарегистрированной TypeLib API7 через `LoadRegTypeLib` с резервным перебором файловых путей через `LoadTypeLibEx`.
- Поиск интерфейсов API7 в загруженной TypeLib.
- QueryInterface к IKompasDocument3D и IEmbodimentsManager.
- Чтение количества исполнений, дерева, текущего индекса.
- Чтение типов обозначения: `-1` (полное), `1` (базовая часть), `2` (номер исполнения).
- Чтение IsVariant.
- Запись результатов в журнал.

## Этап 2 — проверка реального индекса и структуры дерева

По логам пользователя определить:
- фактический диапазон индексов;
- возвращаемый формат GetEmbodimentsTree;
- соответствие индексов значениям дерева;
- какие индексы относятся к вариантам геометрии;
- корректность отдельных частей обозначения.

## Этап 3 — отдельный тест изменения (не включён в 0.1.0)

Только после успешной проверки чтения будет добавлен отдельный тест изменения базовой части. Он будет иметь явное подтверждение пользователя перед COM-вызовом и проверку значений до/после. Не использовать на рабочих документах.
